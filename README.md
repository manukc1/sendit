# Файлы: телефон → компьютер

Одна статическая веб-страница. На компьютере она показывает QR-код, на телефоне открывается
файловый менеджер, и выбранный файл уходит **напрямую на компьютер** (WebRTC, без облака и
загрузки на сервер). Лимит — **25 МБ на файл**.

Всё приложение — один файл `index.html` (~116 КБ). Никаких внешних CDN, библиотек с других
сайтов, регистрации и аккаунтов. Загрузите его на любой бесплатный хостинг — и пользуйтесь
с любого устройства.

```
phone2pc/
├── index.html      ← готовое приложение (это и есть весь сайт)
├── .nojekyll       ← чтобы GitHub Pages не трогал файлы
├── src/            ← исходники (HTML, CSS, JS) — для правок
├── vendor/         ← qrcode.js (MIT, Kazuhiko Arase)
├── build.js        ← сборка index.html из src/ + vendor/
└── README.md
```

## 1. Выложить на GitHub Pages

### Вариант А — через сайт (проще)

1. Зарегистрируйтесь на github.com → **New repository** → имя, например `phone2pc` → **Public** → Create.
2. На странице репозитория: **Add file → Upload files** → перетащите `index.html` и `.nojekyll` → **Commit changes**.
3. **Settings** (вверху) → слева **Pages** → *Build and deployment*:
   - Source: **Deploy from a branch**
   - Branch: **main**, папка **/ (root)** → **Save**.
4. Через 1–2 минуты страница будет доступна:
   `https://ВАШ_ЛОГИН.github.io/phone2pc/`

Дальше открывайте этот адрес на компьютере и сканируйте QR телефоном. Ссылка работает
в любом месте — и дома, и в гостях, и в мобильной сети.

### Вариант Б — через git

```bash
cd phone2pc
git init
git add index.html .nojekyll
git commit -m "phone2pc"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/phone2pc.git
git push -u origin main
```

Затем включите Pages как в пункте 3 выше.

### Другие бесплатные хостинги

| Хостинг | Как | HTTPS |
|---|---|---|
| **Netlify Drop** | app.netlify.com/drop → перетащить папку | да |
| **Cloudflare Pages** | dash.cloudflare.com → Pages → Upload assets | да |
| **Vercel** | vercel.com → New Project → Deploy | да |
| **GitHub Pages** | см. выше | да |
| **Ucoz** | конструктор с рекламой и своей вёрсткой, один HTML-файл туда удобно не положить | — |

**Нужен именно https** (`https://…`). GitHub Pages, Netlify и Cloudflare дают его
автоматически. Открытие файла с диска (`file://`) не подойдёт: телефон не сможет открыть
такую ссылку, да и браузер ограничит часть функций.

## 2. Как пользоваться

1. Откройте страницу на компьютере. Появится QR-код и код комнаты (8 символов).
2. На телефоне: камера → наведите на QR → откройте ссылку.
   (Или откройте тот же адрес и нажмите «Это телефон? Отправить файлы», затем введите код комнаты.)
3. На телефоне нажмите **«Выбрать файлы»** — откроется системный файловый менеджер или галерея.
   Можно выбрать сразу несколько файлов.
4. Передача начинается автоматически; на компьютере появляется строка с прогрессом и кнопка
   **«Скачать»** (или **«Скачать все»**).

Компьютер должен держать страницу открытой до конца передачи. Телефон можно блокировать —
передача продолжится, но лучше не гасить экран.

## 3. Лимит 25 МБ и как его изменить

Лимит проверяется на телефоне **и** на компьютере: файл больше лимита просто не начнёт передаваться.

Изменить можно в `src/index.html` (блок `window.P2F_CONFIG` в конце) и пересобрать:

```bash
node build.js
```

или прямо в готовом `index.html` — найдите в самом конце:

```js
window.P2F_CONFIG = {
  maxFileSize: 25 * 1024 * 1024   // ← 20 * 1024 * 1024, если нужно 20 МБ
};
```

Там же можно поменять `chunkSize`, `highWaterMark`, `brokers` и `iceServers`.

> Файл целиком держится в памяти браузера: на слабом телефоне 25 МБ — уже заметная нагрузка.
> Если нужны файлы больше — поднимайте лимит с осторожностью.

## 4. Как это работает

```
 телефон                                         компьютер
┌──────────────┐   1. QR-ссылка (комната)   ┌──────────────┐
│ файловый     │ ─────────────────────────▶ │ QR + список  │
│ менеджер     │                            │ файлов       │
│              │   2. рукопожатие SDP/ICE   │              │
│              │ ◀──── MQTT-брокеры ──────▶ │              │
│              │      (несколько КБ)        │              │
│              │                            │              │
│              │   3. файл по WebRTC        │              │
│              │ ═════════════════════════▶ │  Blob → «Скачать»
└──────────────┘    напрямую, DTLS-шифр    └──────────────┘
```

- **Сигнализация.** Чтобы два браузера нашли друг друга, им нужно обменяться
  описанием соединения (SDP) и ICE-кандидатами. Для этого страница одновременно
  подключается к трём публичным MQTT-брокерам по WebSocket
  (`broker.emqx.io`, `broker.hivemq.com`, `test.mosquitto.org`) и публикует сообщения
  в топики `p2f/<комната>/h` и `p2f/<комната>/p`. Через них идут только эти несколько
  килобайт — **сами файлы никогда не проходят через брокеры**.
- **Данные.** WebRTC DataChannel, шифрование DTLS. Файл режется на куски по 64 КБ и
  передаётся напрямую, с контролем заполнения буфера.
- **NAT.** STUN-серверы Cloudflare и Google помогают узнать внешний адрес. Для домашнего
  Wi-Fi (телефон и компьютер в одной сети) соединение устанавливается напрямую, без STUN.
- **Комната.** 8 случайных символов; в ссылке — `#r=xxxxxxxx`. Ссылка = приглашение
  в комнату, поэтому не публикуйте её.

## 5. Приватность

- Файлы не загружаются ни на один сервер — они идут с телефона на компьютер.
- Публичные MQTT-брокеры видят только сообщения рукопожатия (SDP с локальными IP-адресами
  устройств). Содержимое файлов им недоступно.
- Нет аналитики, счётчиков, куки и внешних шрифтов.

## 6. Если не работает

| Симптом | Что делать |
|---|---|
| «Компьютер не в сети» | Обновите страницу на компьютере, отсканируйте новый QR. Проверьте, что на компьютере открыта именно эта страница. |
| Долго «Подключение к серверу…» | Публичные MQTT-брокеры могут блокироваться корпоративным Wi-Fi или провайдером. Попробуйте другую сеть или добавьте свой брокер в `brokers`. |
| Соединение не устанавливается в мобильной сети | У оператора часто CGNAT, а бесплатного TURN в комплекте нет. Дома (телефон и ПК в одной Wi-Fi-сети) работает всегда. Для гарантии через интернет добавьте свой TURN-сервер в `iceServers`. |
| Файл «завис» на 0 % | Обновите страницу на телефоне и подключитесь заново; проверьте, что компьютер не ушёл в сон. |
| На iPhone файл не сохраняется | После передачи на компьютере нажмите «Скачать»; на самом iPhone Safari сохраняет через «Поделиться → Сохранить в Файлы». |
| Обновил страницу — пропал список файлов | Полученные файлы живут в памяти вкладки. Скачайте их сразу после передачи. |

## 7. Разработка

```bash
node build.js        # собрать index.html из src/ и vendor/
node --check src/app.js
```

Структура исходников:

- `src/index.html` — разметка и `P2F_CONFIG`;
- `src/style.css` — стили;
- `src/app.js` — сигнализация (мини-клиент MQTT), WebRTC, передача файлов, UI.

В `_test/` (вне этой папки, не входит в сайт) лежит сквозной тест на Puppeteer:
он поднимает Chrome, открывает две вкладки («компьютер» и «телефон»), передаёт файл
и сверяет SHA-256.
